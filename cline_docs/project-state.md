# Текущее состояние

## Текущая фаза

MVP Telegram-бота развёрнут как Railway Worker и подтверждён live-проверкой с телефона. Исправлена логика шага «Пройти регистрацию»: новый пользователь получает стартовую ссылку из очереди, повторно новая ссылка не выдаётся, а пользователю показывается его ранее выданная или уже сохранённая личная ссылка. Дополнительно бот теперь определяет куратора как владельца выданной ссылки: для стартовых ссылок — по стартовому списку, для следующих уровней — по `owner_user_id` и `username` владельца ссылки. Следующая фаза — пройти полный business-flow на production и подготовить операционные инструкции для куратора.

## Подтверждённые решения

- Модель 3×3 реализована как FIFO-очередь активных реферальных ссылок.
- Одна активная ссылка выдаётся максимум трём новичкам.
- Порядок выдачи: по времени активации, затем по ID ссылки.
- Новый пользователь получает стартовую ссылку из очереди на шаге «Пройти регистрацию».
- Если стартовая ссылка уже выдавалась ранее, бот не расходует новую и показывает пользователю ранее выданную ссылку с подсказкой обратиться к куратору.
- Куратор определяется как владелец выданной ссылки: для стартовых 4 ссылок — из стартового списка, для пользовательских ссылок — по `username`/имени владельца ссылки.
- После регистрации пользователь получает код `BiNi-XXXX`, меняет ник Binibit на `Имя | BiNi-XXXX` и присылает свою реферальную ссылку.
- Ссылка хранится в базе, но не выдаётся другим до подтверждённого стейкинга.
- Пользователь присылает один скрин активного стейкинга.
- Куратор вручную одобряет или отклоняет заявку.
- После одобрения ссылка добавляется в конец очереди и становится активной.
- API Binibit не используется: подтверждённой интеграции для рефералов, регистрации или стейкинга нет.
- Бот не запрашивает документы, пароли, 2FA-коды или API-ключи и не обещает доходность.

## Что реализовано

- `bot/database.py` — SQLite-схема и слой подключения.
- `bot/referral_manager.py` — FIFO-выдача, лимит трёх выдач, статусы и решения куратора, а также чтение ранее выданной стартовой ссылки, личной ссылки пользователя и имени куратора-владельца ссылки.
- `bot/quiz_flow.py` — стартовое меню и информационные шаги пользователя; содержит кнопки «Открыть BiNiBit» и «Нужна помощь?».
- `bot/registration_flow.py` — регистрация, повторный показ ранее выданной стартовой ссылки, показ личной ссылки после регистрации, определение куратора по владельцу выданной ссылки, приём реферальной ссылки и скрина.
- `bot/admin_flow.py` — добавление стартовых ссылок и обработка решений куратора.
- `bot/bot_core.py` — точка входа и регистрация обработчиков aiogram; передаёт `SUPPORT_URL` в стартовую клавиатуру.
- `bot/content.json` — пользовательские тексты.
- `bot/tests/test_referral_manager.py` — тесты ядра FIFO, повторного получения ранее выданной / личной ссылки и определения куратора-владельца ссылки.
- Корневые `Dockerfile` и `.dockerignore` — Railway-сборка только из папки `bot/`, без секретов, базы и исходных медиа.
- `RAILWAY_DEPLOY.md` — инструкция Railway.
- `bot/Dockerfile`, `bot/docker-compose.yml`, `bot/.dockerignore`, `bot/DEPLOY_VPS.md` — альтернативный Docker-деплой на VPS.

## Ограничения и риски

- Полный живой сценарий ещё не пройден: выдача стартовой ссылки → регистрация → скрин → решение куратора → активация → FIFO-выдача новой ссылки.
- Локальная Docker-сборка не проверена: Docker CLI на Windows не установлен.
- Неотслеживаемые в Git PDF, DOCX, MP4, JPG, XLSX, RTF и рабочие markdown-файлы в корне проекта не включать в кодовый commit без отдельного решения.
- При утечке токена нужно немедленно выполнить `/revoke` в BotFather, заменить `BOT_TOKEN` в Railway и redeploy.
