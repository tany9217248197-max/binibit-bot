# Текущее состояние

## Текущая фаза

Базовый MVP Telegram-бота реализован и локально проверен. Следующая фаза — ручная проверка пользовательского Telegram-сценария с тестовыми данными куратора.

## Подтверждённые решения

- Модель 3×3 реализована как FIFO-очередь активных реферальных ссылок.
- Одна активная ссылка выдаётся максимум трём новичкам.
- Порядок выдачи: по времени активации, затем по ID ссылки.
- Новый пользователь получает код `BiNi-XXXX` и меняет ник Binibit на `Имя | BiNi-XXXX`.
- Пользователь присылает свою реферальную ссылку после регистрации.
- Ссылка хранится в базе, но не выдаётся другим до подтверждённого стейкинга.
- Пользователь присылает один скрин активного стейкинга.
- Куратор вручную одобряет или отклоняет заявку.
- После одобрения ссылка добавляется в конец очереди и становится активной.
- API Binibit не используется: подтверждённой интеграции для рефералов, регистрации или стейкинга нет.
- Бот не запрашивает документы, пароли, 2FA-коды или API-ключи и не обещает доходность.

## Актуальные статусы

```text
submitted → pending_staking → pending_review → active → limit_reached
                                              ↘ rejected
```

## Что реализовано

- `bot/database.py` — SQLite-схема и слой подключения.
- `bot/referral_manager.py` — FIFO-выдача, лимит трёх выдач, статусы и решения куратора.
- `bot/quiz_flow.py` — информационные шаги пользователя.
- `bot/registration_flow.py` — регистрация, приём реферальной ссылки и скрина.
- `bot/admin_flow.py` — добавление стартовых ссылок и обработка решений куратора.
- `bot/bot_core.py` — точка входа и регистрация обработчиков aiogram.
- `bot/content.json` — пользовательские тексты.
- `bot/tests/test_referral_manager.py` — тесты ядра FIFO.
- `bot/.env.example` — шаблон конфигурации без секретов.
- `.gitignore` — исключает `.env`, SQLite-базы, `.venv` и кэши.

## Ограничения и риски

- Настоящий Telegram-поток пока не проверен с реальным `BOT_TOKEN` и `ADMIN_TELEGRAM_IDS`.
- В проекте нет настроенного Git remote, поэтому синхронизация между устройствами пока не включена.
- Исходные PDF, DOCX, MP4 и изображения не должны автоматически входить в первый кодовый checkpoint без отдельного решения по хранению крупных материалов.
