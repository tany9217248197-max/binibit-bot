# Master plan: Telegram-бот BiNiBit 3×3

## Цель

Создать Telegram-бота, который мягко сопровождает новичка от знакомства с BiNiBit до регистрации, верификации, пополнения и стейкинга.

После подтверждённого стейкинга ссылка участника активируется в модели 3×3: каждая активная реферальная ссылка может быть выдана максимум трём следующим новичкам. Новые подтверждённые ссылки добавляются в конец очереди, поэтому система распределяется сверху вниз и слева направо.

## Scope MVP

- Telegram-бот на Python и aiogram 3.x.
- SQLite для локального запуска и пилота.
- Контент в `content.json`.
- Уникальный идентификатор новичка формата `BiNi-XXXX`.
- Сохранение реферальной ссылки пользователя после регистрации.
- Один скрин активного стейкинга как заявка на проверку.
- Ручное одобрение или отклонение заявки куратором.
- FIFO-очередь активных ссылок с лимитом три выдачи на ссылку.
- Уведомление ожидания, если на переходном этапе не осталось активных ссылок.
- Базовая аналитика этапов в SQLite.

## Non-scope MVP

- Использование API-ключей Binibit.
- Автоматическая проверка регистрации, KYC, депозита или стейкинга.
- Торговые операции, вывод средств, работа с чужими аккаунтами.
- Запрос документов, паролей, кодов 2FA и API-ключей.
- Автоматизация через Google Sheets.
- Деплой на VPS до локальной проверки MVP.

## Подтверждённые продуктовые правила

1. Модель 3×3 сохраняется:
   - каждая активная ссылка выдаётся максимум трём новичкам;
   - FIFO определяет, какая активная ссылка получает следующие позиции;
   - после проверки стейкинга ссылка нового участника добавляется в хвост очереди.

2. После регистрации пользователь:
   - получает код `BiNi-XXXX`;
   - меняет отображаемый ник Binibit на `Имя | BiNi-XXXX`;
   - отправляет боту свою реферальную ссылку;
   - остаётся в статусе ожидания стейкинга, пока не вернётся позднее.

3. После запуска стейкинга пользователь отправляет один скрин. Куратор вручную проверяет код, ссылку и скрин и принимает решение.

4. Сроки стейкинга: 30, 90, 180 или 360 дней. На финансовых шагах бот сообщает, что актуальные условия и возможные риски нужно проверять в личном кабинете и на официальной площадке BiNiBit.

5. Бот не обещает доходность и не подталкивает пользователя к финансовому решению.

## Статусы ссылки

```text
submitted        — пользователь передал ссылку
pending_staking  — ожидается запуск стейкинга
pending_review   — получен скрин, ожидается проверка куратора
active           — ссылка добавлена в очередь и может быть выдана
limit_reached    — ссылка выдана три раза
rejected         — заявка отклонена куратором
```

## Пользовательский поток

```text
/start
  ↓
Знакомство / риски / информация о стейкинге
  ↓
Регистрация на официальной площадке
  ↓
Код BiNi-XXXX и инструкция по нику
  ↓
Пользователь отправляет свою реферальную ссылку
  ↓
Гайд «Как внести депозит?» и справка о стейкинге
  ↓
Пользователь возвращается, отправляет скрин активного стейкинга
  ↓
Куратор: одобрить / отклонить
  ↓
Ссылка активна и стоит в конце FIFO-очереди
```

```text
  .clineignore
  tests/
```

## Фазы

### Фаза 1 — документы и каркас
Definition of done:
- старые планы заменены актуальной моделью;
- создана структура Python-проекта;
- `.env.example` и `.clineignore` исключают секреты и локальную БД.

### Фаза 2 — ядро данных
Definition of done:
- SQLite создаёт таблицы;
- `get_referral_link()` атомарно выдаёт первую доступную ссылку и увеличивает счётчик;
- ссылка становится активной только после решения куратора.

### Фаза 3 — Telegram-сценарий
Definition of done:
- пользователь проходит старт, регистрацию, передачу ссылки и отправку скрина;
- куратор может одобрить или отклонить заявку;
- админ может добавить стартовую ссылку вручную.

### Фаза 4 — проверка
Definition of done:
- автоматические тесты проверяют FIFO-порядок, лимит 3 и модерацию;
- исходный код проходит проверку компиляции;
- инструкция запуска актуальна.

### Фаза 5 — Git и handoff
Definition of done:
- создан локальный Git-репозиторий;
- секреты не попадают в индекс;
- подготовлены `cline_docs/project-state.md` и `cline_docs/handoff-summary.md`;
- при подключённом remote выполнены commit и push.

## Риски и ограничения

- API Binibit по текущей документации не предоставляет подтверждённые методы для рефералов, регистрации или стейкинга.
- Подтверждение стейкинга до появления партнёрского API выполняется вручную.
- Тексты финансовых шагов должны оставаться информационными и ссылаться на актуальные условия платформы.
